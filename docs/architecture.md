# Architecture

How GDK.Net is layered, why the interop layer is checked in, and what actually differs between the
three target frameworks.

The binding rulebook is
[`../eng/interop-conventions.md`](../eng/interop-conventions.md), which is normative for anyone
adding a family.

## Two layers

```
  your title
      │
      ▼
  GDK.Net           idiomatic public API: Task, IDisposable, events, exceptions, [Flags] enums
      │             src/GDK.Net/<Family>/*.cs
      ▼
  GDK.Net.Interop   internal raw P/Invoke: blittable only, one file per family
      │             src/GDK.Net/Interop/Native.<Family>.cs + NativeTypes.<Family>.cs
      ▼
  native modules    xgameruntime.thunks.dll, Microsoft.Xbox.Services.C.Thunks.dll,
                    and six PlayFab extension libraries
```

`GDK.Net.Interop` is `internal`. Nothing in it is part of the supported surface, which is why the
[API reference](api/) does not list it.

For a family `Xyz`, the layout is fixed:

| File | Contents |
|---|---|
| `src/GDK.Net/Interop/Native.Xyz.cs` | `internal static unsafe partial class Native`: the P/Invokes |
| `src/GDK.Net/Interop/NativeTypes.Xyz.cs` | raw enums and blittable structs transcribed from the header |
| `src/GDK.Net/Xyz/*.cs` | the idiomatic public API |
| `tests/GDK.Net.Tests/XyzTests.cs` | contract tests |

## The native modules

The projection binds the **thunks** DLLs, not `XGameRuntime.dll` itself:

| Module | Surface | Opt-in flag |
|---|---|---|
| `xgameruntime.thunks.dll` | The Gaming Runtime (`X*`) | always |
| `Microsoft.Xbox.Services.C.Thunks.dll` (+ `libHttpClient.dll`) | XBOX Live Services (`Xbl*`), reached via `GameRuntime.XboxLive` | `GdkNetIncludeXboxLive` |
| `PlayFabCore.dll`, `PlayFabServices.dll`, `PlayFabGameSave.dll` | PlayFab | `GdkNetIncludePlayFab` |
| `PlayFabMultiplayer.dll` | PFMP lobbies and matchmaking | `GdkNetIncludePlayFabMultiplayer` |
| `Party.dll`, `PartyXboxLive.dll` | Party | `GdkNetIncludePlayFabParty` |

Redistribution is handled by `eng/packaging/GdkRedist.targets`, which copies the DLLs from
`%GameDKCoreLatest%windows\bin\<arch>` next to the output. A title that does not use a family does
not ship its DLL.

Not every declared API is reachable. `eng/unexported-apis.md` records the entry points that exist
in the import libraries or headers but are absent from the redistributable thunks DLLs, split by
whether they are genuinely missing, internal-only, or compiled out on GDK. See
[gdk-edition.md](gdk-edition.md) for how to re-derive that list correctly.

## Why the interop layer is checked in

`src/GDK.Net/Interop/` is hand-authored and committed, not generated during the build.

ClangSharp output (`eng/generate-interop.ps1` → the git-ignored `eng/Generated/`) is the
**authoritative signature reference**: never guess a signature, but it is deliberately not
compiled. It emits `[assembly: DisableRuntimeMarshalling]` and uses `bool` in P/Invoke signatures,
neither of which works on `netstandard2.0`. It also declares the same type names in the same
namespace, so it cannot supplement the hand-authored files; adopting it would mean replacing them.

The practical consequence is the one that matters day to day: **building and testing this repo
needs no GDK install**, which is what lets hosted CI build it.

The PlayFab projection is different: it *is* generated, by the Python emitters under
`eng/playfab/`, and that generated C# is committed. Files carry an `<auto-generated>` banner naming
the emitter. Edit the emitter, then re-run `eng/generate-playfab.ps1`; never hand-edit the output.

## Target frameworks

`net8.0;net10.0;netstandard2.0`. The three export an *identical* public surface: verified at
11798 public and protected entries each, with no member present on one target and absent from
another. What differs is entirely how that surface is implemented.

| | `net8.0` / `net10.0` | `netstandard2.0` |
|---|---|---|
| P/Invoke | `[LibraryImport]`, source-generated | `[DllImport]` |
| Native callbacks | `[UnmanagedCallersOnly]` + function pointers | `Marshal.GetFunctionPointerForDelegate` + delegate fields |
| AOT / trim analyzers | on | off (not available) |
| `IsTrimmable` marker | applied | not applied |
| Intended consumer | .NET titles, tools, services | MonoGame / Mono / broad reach |

Both P/Invoke shims live in the same file, guarded by `#if NET7_0_OR_GREATER`, and must stay
signature-identical. Only blittable parameters are used, so the two generate equivalent stubs.

The delegate-versus-function-pointer split is the substantive difference: `[UnmanagedCallersOnly]`
allocates no delegate and needs no runtime code generation, which is what makes the net8+ targets
AOT-safe. `netstandard2.0` is never AOT-published, so it keeps the delegate path. The delegate
types this introduces are `internal`, which is why the split does not reach the public surface.

> The [API reference](api/) is generated from the `net10.0` build only. Because the public surface
> is the same on all three targets, it is complete for every target. Keep it that way: a public
> member added behind a `#if` would not appear in the reference. Put target-specific code behind
> an `internal` type, as the existing guards do.

## The AOT contract

XBOX consoles require NativeAOT, so the library must be usable from an AOT-published title. Three
things enforce that:

1. **The analyzers.** `EnableAotAnalyzer`, `EnableTrimAnalyzer` and `EnableSingleFileAnalyzer` are
   set individually in `GDK.Net.csproj`: deliberately *not* via `IsAotCompatible`, because that
   also sets `IsTrimmable`, which changes NuGet packaging semantics. The `IsTrimmable` assembly
   metadata is applied directly instead.
2. **`TreatWarningsAsErrors`.** Set repo-wide in `Directory.Build.props`, so any `IL2xxx`/`IL3xxx`
   diagnostic fails the build. This is what stops a future family from reintroducing reflection or
   runtime-generated marshalling stubs.
3. **A real ILC compilation.** `eng/package.ps1 -Aot` and `eng/run-local.ps1 -Aot` perform the
   actual NativeAOT publish. This is the ground truth, and the reason the analyzers can be disabled
   with `GdkNetEnableAotAnalyzers=false` on a machine whose NuGet feeds cannot serve
   `Microsoft.NET.ILLink.Tasks`.

### The `netstandard2.0` publish trap

A consumer that runs `dotnet publish -p:PublishAot=true` sets an MSBuild **global** property, which
flows into every `ProjectReference` and cannot be overridden by an ordinary `PropertyGroup`.
`netstandard2.0` cannot be AOT-compiled, so the consumer's publish would fail with `NETSDK1207`
pointing at *this* project.

The `GdkNetDisableAotForNetStandard` target clears `PublishAot`, `PublishTrimmed` and
`PublishReadyToRun` just before `ProcessFrameworkReferences`: properties assigned inside a target
do override globals, so `ProjectReference` consumers keep working while `net8.0` and `net10.0` are
still compiled ahead of time. Package consumers never hit this, because NuGet resolves a single
nearest target framework.

## Threading

`X*` callbacks arrive on the process default task queue's thread pool; the projection keeps task
queues internal and surfaces `Task`. Nothing needs pumping.

PlayFab Party is the exception: it is an object model that must be pumped from the title's frame
loop, which is why `src/GDK.Net/PlayFab/Party` is hand-written rather than generated.
